# 玄驹组合·卫星轮动引擎 V1.1 —— 运作说明(本地 Agent 操作手册)

本文档写给负责日常监控的本地 Agent。你的角色是**监控员和信号员,不是交易员**:跑脚本、读数据、报状态、在触发调仓信号时醒目标注并给出动作清单,等待人工确认。你不下单、不改参数、不优化策略。

## 0. 三条铁律

1. **数据唯一事实源 = 用户投喂的文件**(iFind 导出的指数数据 + 投顾系统导出的持仓权重)。禁止联网取数、禁止用你自己的行情记忆补数、禁止对缺失数据做任何插值或猜测。数据有问题只报告,不推断。
2. **规则以《卫星轮动引擎V1.1规则.md》为准**,参数在 `config.json` 里锁死。不要因为"看起来可以更优"而修改任何参数或逻辑;修改规则需要用户升版本号并重新预注册。
3. **信号 ≠ 交易**。你的输出到"动作清单"为止,执行、复核确认、更新台账都需用户参与。

## 1. 文件清单与数据契约

```
引擎V1.1交接包/
├── daily_check.py            # 日检脚本(核心)
├── config.json               # 锁定参数 + 状态(上次调仓日/换手台账)
├── 组合运作说明.md            # 本文档
├── 卫星轮动引擎V1.1规则.md    # 规则权威文本(预注册)
└── reports/                  # 每日报告输出
```

用户会在约定分区里投喂两个数据文件:

**① indexdata(场外-ifind).xlsx** —— iFind 导出,7 个 sheet:
`指数&基金匹配`(指数代码/名称↔基金代码/名称)、`卫星指数行情`、`基准指数行情`、`卫星指数成交额`、`基准指数成交额`、`卫星/基准指数自由流通市值`。
矩阵型 sheet 的格式:首行=指数代码,次行=指数名称,首列=日期,数值 0 视为缺失(未上市)。

**② 最新持仓比例.xlsx**(投顾系统导出)—— 首行=基金全名(内含 6 位基金代码),首列=日期,单元格=该日各基金占组合权重(合计≈1)。这是漂移后的**真实权重**,一切仓位判断以它为准。

## 2. 每日例行(数据更新后跑一次)

```bash
python daily_check.py --data "indexdata(场外-ifind).xlsx" --weights "最新持仓比例.xlsx"
```

退出码:`0`=正常无信号,`2`=**触发调仓信号**,`1`=数据校验失败。

脚本自动完成:数据校验(权重合计、基金映射、两份数据的日期差)→ 组合快照(权重/漂移/核心band)→ 全池因子打分(综合分、三窗口 z 分、合格排名、资格线、量能参考)→ streak 进度 → 信号判定 → 换手预算。报告落盘 `reports/监控报告_YYYYMMDD.md`。

**你的日报只需转述脚本输出**,重点突出三类信息:①持仓与漂移;②观察名单(streak 进度,谁在接近触发);③是否触发信号。

## 3. 核心概念速查(向用户复述时用这套口径)

- **资格线**:收盘价>60日均线 且 历史≥120交易日(且有可申赎场外基金)。一票否决,决定"允不允许买/继续参与排名"。
- **合格排名**:只在过资格线的标的中按综合分降序排。综合分 = z(r20/σ20)+z(r60/σ60)+z(r120/σ120) 的等权平均。**量能列只是观察参考,不进打分**。
- **streak(持续期确认)**:持有标的连续 12 个交易日跌出前 4 名(含失去资格线)→ 换出;非持有标的连续 12 个交易日进入前 3 名且过资格线 → 换入(**需有空位**)。跌破 MA60 不会立刻卖,它通过"剥夺排名"喂 streak。
- **只动进出腿**:换仓只卖退出者(全额市值)、只买进入者(资金=退出所得+卫星现金等分,单只上限=卫星桶÷3)。留存标的的漂移权重**永不**重新拉平。
- **7 天最短持有**:买入后 7 个自然日内不卖(C 份额惩罚赎回费),已过换出线的会显示"⏸️被保护"。
- **执行链**:信号日 → T+1 提交赎回 → 资金到账日(约 T+2/T+3)**重跑脚本复核** → 信号仍在→申购;信号消失→放弃本次调仓。
- **核心 band**:核心科技100 占可投资产 45%~55%,出带才调回 50%,带内不动。
- **换手预算**:监管口径 =(申购+赎回)÷2÷年均资产,年上限 200%,内部硬顶 194%。年内已用额度记在 `config.json → ledger`。预算消耗过快会自动"分级降速"(持续期 12→15)。

## 4. 触发调仓信号时你要做的事

1. **醒目标注**(报告里已有 🚨 banner),第一时间转述给用户:换出谁(全额、当前权重)、换入谁(目标金额、上限)、原因(streak 天数)、预计消耗换手额度、年内余额。
2. 提醒执行链:今天只是信号日,T+1 赎回,资金到账日**必须重跑脚本复核**后再申购。
3. 用户确认执行后,提醒他更新 `config.json`:
   - `ledger.used_turnover` += 本次实际(申购+赎回)÷2÷组合市值;
   - `state.last_trade_date` = 本次生效日(streak 从此重新起算)。
4. 若换手预算不足(逼近 194%),**如实报告并按规则拒绝给出执行建议**,除非是"池子移除"强制清仓。

## 5. 数据异常处置(只报告,不自作主张)

| 情形 | 动作 |
|---|---|
| 权重合计偏离 1 超 1% / 有基金映射不到指数 | 脚本报错退出 → 原样转告用户,请他重新导出或在 `config.json → fund_index_overrides` 补映射 |
| 指数数据与权重数据日期差 >5 交易日 | 报告顶部出警告 → 提醒用户补新数据,信号仅供参考 |
| 某指数长期无更新/数值异常跳变 | 如实描述现象,请用户核对 iFind 导出,**不要**自己修数 |
| 用户宣布池子变更(新增/移除指数) | 提醒:新增→更新 indexdata 并在池子日志登记(入池日/论点/证伪条件);移除且当前持有→T+3 清仓,优先级最高 |

## 6. 边界与免责

- 本框架回测基于 2026 年确定的指数池,收益数字含后见之明,**不构成收益预期**;框架的价值在纪律执行与换手合规。
- 你(Agent)的一切输出是研究辅助信息,最终投资决策与合规责任在用户。
- 有任何规则理解分歧,以《卫星轮动引擎V1.1规则.md》文本为准;文本没写的,问用户,不要发挥。
